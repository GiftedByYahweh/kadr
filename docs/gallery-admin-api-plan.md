# Plan: Gallery Admin API (part 1, no photos)

## Context

Kadr is a photographer's portfolio plus client galleries. We are working on
galleries now: the photographer creates a gallery in the admin, uploads photos,
the client gets a secret link, views, likes, comments and downloads.

Read before starting:

- `AGENTS.md` — project rules (architecture, style, prohibitions). Mandatory.
- `docs/gallery-features.md` — gallery features and decisions made.

A finished module to use as a reference: `apps/api/src/modules/auth/`
(entities, repositories, mappers, use cases, routes, schemas) and its wiring in
`apps/api/src/container/auth.container.ts`.

## Scope

This part covers only the gallery itself: create, list, settings, trash,
delete, share link regeneration.

**Out of scope** (separate tasks later): photo upload, previews, worker, R2,
client likes and comments, client API (`/api/gallery/*`), trash cleanup cron,
admin UI.

## 1. Migration

- Remove the `archived` status from `GalleryStatus` (`packages/shared/src/gallery/constants.ts`)
  and from the Postgres enum `gallery_status`. `active` and `trashed` remain.
- Add the column `galleries.trashed_at` (`timestamptz`, nullable) — the moment
  the gallery was moved to trash; the 30 days are counted from it.
- Add the column `galleries.currency` — Postgres enum `currency`
  (`UAH`, `EUR`, `USD`) from the `Currency` dictionary in `@kadr/shared`, `NOT NULL`.
  The currency applies to `extraPrice`.
- Generate the migration with `pnpm --filter @kadr/api db:generate`, review the SQL
  (Postgres removes an enum value by recreating the type), apply it with
  `pnpm --filter @kadr/api db:migrate`. Do not use `drizzle-kit push`.

## 2. Config

- New variable `GALLERY_URL` (locally `http://localhost:5181`, in production
  `https://gallery.kadr.xx`).
- Add it to `.env.example`, `apps/api/src/config.ts` (via `requireEnv`) and to
  `x-api-environment` in `docker-compose.yml`.
- Used so the api returns a ready `shareUrl` = `GALLERY_URL/<shareToken>`;
  the admin does not know the gallery domain.

## 3. Endpoints

All in the admin zone, behind the admin guard. Add the paths to `AdminApiRoutes`
(`packages/shared/src/api/routes/admin.ts`); path strings are not written anywhere else.
Each photographer sees and changes only their own galleries (`user_id` from the session).

| Method   | Path                                   | What it does                  |
| -------- | -------------------------------------- | ----------------------------- |
| `GET`    | `/api/admin/galleries`                 | List (paginated, with search) |
| `GET`    | `/api/admin/galleries/counts`          | Number of active and trashed  |
| `POST`   | `/api/admin/galleries`                 | Create                        |
| `GET`    | `/api/admin/galleries/:id`             | One gallery                   |
| `PATCH`  | `/api/admin/galleries/:id`             | Update settings               |
| `POST`   | `/api/admin/galleries/:id/trash`       | Move to trash                 |
| `POST`   | `/api/admin/galleries/:id/restore`     | Restore from trash            |
| `DELETE` | `/api/admin/galleries/:id`             | Delete permanently            |
| `POST`   | `/api/admin/galleries/:id/share-token` | Regenerate the share link     |

One route = one use case (`CreateGalleryUseCase`, `ListGalleriesUseCase`,
`CountGalleriesUseCase`, `GetGalleryUseCase`, `UpdateGalleryUseCase`, `TrashGalleryUseCase`,
`RestoreGalleryUseCase`, `DeleteGalleryUseCase`, `RegenerateShareTokenUseCase`).

### Request bodies

- **List (query):** `status` (`active` or `trashed`), `search` (optional,
  case-insensitive search by title), `page` (from 1), `pageSize` (up to 50).
  Response `{ items, hasNextPage }`; for `hasNextPage` we select `pageSize + 1` rows.
- **Counts:** response `{ active, trashed }`.
- **Create:** `title`, `expiresAt` (ISO date or `null` = no limit),
  `includedCount`, `extraPrice`, `currency`.
- **Update:** the same five fields, all optional.
- **Restore:** `expiresAt` (optional, see the rules below).
- **Delete (query):** `confirmTitle` — must exactly match the gallery title.

Zod request schemas live in `@kadr/shared` so the admin uses the same ones.

## 4. What we return (DTOs in `@kadr/shared`)

**List item** `AdminGalleryListItemDto`:
`id`, `title`, `status`, `expiresAt`, `trashedAt`, `createdAt`, `includedCount`,
`extraPrice`, `currency`, `selectionSubmittedAt`, `mediaCount`, `likedCount`,
`coverUrl` (always `null` for now, there are no photos yet).

**One gallery** `AdminGalleryDto`: everything from the list item plus `shareUrl`.

Dates are ISO strings. Fields are picked deliberately in the mapper, the entity
is never returned directly. `shareToken` is not returned separately, only `shareUrl`.

## 5. Business rules

- **Create:** `status = active`, `shareToken` is generated by the existing `TokenService`
  (`apps/api/src/common/tokens/`). Status and defaults are set in the use case, not in the mapper.
- **Someone else's or non-existent gallery** → the same error `GALLERY_NOT_FOUND`
  (we do not reveal that someone else's gallery exists).
- **A trashed gallery** cannot be edited and cannot regenerate its link →
  `GALLERY_TRASHED`. It can only be restored or deleted.
- **Trash:** `status = trashed`, `trashed_at = now`. The client link
  stops working (the client API will take the status into account).
- **Restore:**
  - if `expiresAt` has not passed yet or is `null` — restore immediately;
  - if it has already passed — a new `expiresAt` is required in the body (in the
    future or `null`), otherwise `GALLERY_RESTORE_NEEDS_EXPIRY`;
  - after restoring `status = active`, `trashed_at = null`.
- **Permanent delete:** available for both an active and a trashed gallery.
  `confirmTitle` does not match → `GALLERY_TITLE_MISMATCH`. First collect the
  `storage_key` / `preview_key` of its media, delete the rows (media and comments
  go by cascade), and **after** the successful DB delete remove the files via
  `FileStorage.delete` (`apps/api/src/common/storage/`). Files are outside the transaction.
- **Link regeneration:** new token, the old link is dead immediately.
- Trash, restore and regeneration return `AdminGalleryDto`;
  delete returns nothing.
- The current time (`new Date()`) is taken in the use case and passed into pure
  functions of `gallery.service.ts`; services never read the clock themselves.

## 6. Errors

Add to `DomainErrorCode` (`packages/shared/src/errors/domain.ts`) and always
to `HTTP_STATUS_BY_APP_ERROR` (`apps/api/src/common/error/http-status.map.ts`):

| Code                           | HTTP  |
| ------------------------------ | ----- |
| `GALLERY_TRASHED`              | `409` |
| `GALLERY_RESTORE_NEEDS_EXPIRY` | `400` |
| `GALLERY_TITLE_MISMATCH`       | `400` |
| `GALLERY_EXPIRY_IN_PAST`       | `400` |

`GALLERY_NOT_FOUND` already exists.

## 7. Limits (in `@kadr/shared`, shared by Zod, DB and UI)

- title: 1–120 characters, trimmed;
- `includedCount`: 0–1000;
- `extraPrice`: integer in the gallery currency, 0–100 000;
- list `pageSize`: 1–50.

## 8. Steps

Each step ends with green typecheck/lint/format and a separate commit.

1. **Foundation:** `@kadr/shared` (statuses, currency, limits, DTOs, Zod schemas,
   error codes, paths), table + migration, `GALLERY_URL` in config.
2. **Reads:** entity, repository, mapper, `gallery.service.ts`; list,
   counts, one gallery; routes + container.
3. **Writes:** create, update, link regeneration.
4. **Trash and delete:** trash, restore, permanent delete with files.
5. **End-to-end check:** all endpoints and errors by hand, a second user.

## 9. Checks before handing over

2. Run locally (`pnpm dev`), create a user
   (`pnpm --filter @kadr/api user:create`), log in and go through every endpoint
   by hand (curl / HTTP client): success scenarios and every error from section 6.
3. Check that someone else's gallery is not visible (second user).
4. No comments in code, no `enum`, no new packages without approval.
5. No tests for now.
